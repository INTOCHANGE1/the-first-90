# THE FIRST 90 — APP BUILD SPECIFICATION

This is the master specification for building the digital version of THE FIRST 90, a 12-week men's transformation journal under THE NEW AGE MAN brand.

This document is the source of truth. Reference it for any decision about what to build.

---

## 1. PRODUCT OVERVIEW

### What it is
A web app that delivers a 12-week structured journal experience for men entering THE NEW AGE MAN ecosystem. Clients log in from any device, write daily, and the app autosaves their progress.

### Who it's for
Men aged 25 to 55 who have purchased a NEW AGE MAN program. Most are not technical. Many are reading or writing on a phone at 6am or 9pm. The UI must be calm, masculine, and friction-free.

### What it does
- Authenticates clients via Google sign-in
- Validates a one-time invite code on first signup (codes are issued when a client buys a NAM program)
- Walks the client through a 12-week structured journal across three phases
- Autosaves every input as the client writes
- Tracks streaks on the daily non-negotiables habit grid
- Renders the Wheel of Life as an interactive 10-segment, 10-ring rating tool
- Allows the client to access their journal from any device, picking up where they left off

### What it does NOT do (out of scope for v1)
- No coach dashboard. The founder does not see client writing.
- No social features, brotherhood feed, or in-app messaging.
- No payment processing. Access is gated by invite codes only.
- No push notifications in v1. Add later if needed.
- No PDF export in v1. Add later if needed.
- No sharing or public profiles.

## 4. AUTHENTICATION & ACCESS FLOW

### First-time user
1. Lands on marketing/landing page (or directly on `/signup` from a NAM email)
2. Enters their invite code (e.g. `NAM-A4F2K9`)
3. Code is validated against `invite_codes` table (must be active and unused)
4. If valid, they sign in with Google
5. On first sign in, a `profiles` row is created, `invite_code_used` and `program_source` are set, the code is marked as used
6. They're routed to a brief 4-step onboarding:
   - Welcome screen (Ben's letter, scroll to bottom to continue)
   - Display name capture (first name only)
   - Timezone confirmation (auto-detect, allow override)
   - "Pick up the pen" CTA → routes to first front matter page (Line in the Sand)

### Returning user
1. Lands on `/login`
2. One-tap Google sign-in
3. Routed to `/journal` which is their personal dashboard

### Code generation
The founder needs a simple admin route (or just direct DB access via Supabase) to generate invite codes in batches. For v1, this can be a simple SQL function or a CSV upload. Format: `NAM-XXXXXX` (6 alphanumeric chars).

### Edge cases
- Invalid code → "This code isn't valid. Check with the team that issued it."
- Used code → "This code has already been used."
- Returning user signs in but has no profile → fallback to invite code entry
- User signs in with a different Google account than first time → treat as new user (this is fine, they would need a new code)

### Dashboard logic (`/journal`)
The dashboard is the most important screen. It must answer in one glance: "What do I do today?"

Layout (top to bottom):
1. Greeting line: "Morning, [first name]. Day [N] of 90."
2. Phase progress bar showing 1/3 phases, day-in-phase
3. **Today's call to action card** — the most prominent element
   - Morning page card if morning_completed_at is null
   - Evening page card if evening_completed_at is null
   - Sunday review card if it's Sunday and review is incomplete
   - Phase reset card if the phase is complete and reset isn't done
   - "All done for today" state with a quote if everything's complete
4. Habit grid quick-tick — current week's row only, with checkmarks
5. Quick links: This week, This phase, All phases
6. Reset link tucked at the bottom: "Fell off? Read this."

### Day-numbering logic
- Day 1 = the day they first signed up (in their timezone)
- Day count advances at midnight in their timezone
- If they miss days, the day count keeps advancing — they can backfill but the calendar is real
- If they miss 3+ days, the dashboard surfaces the reset page first
- After day 84, they're routed to back matter

## 6. AUTOSAVE BEHAVIOUR

### Rules
- Every text input autosaves on blur (when focus leaves the field) AND on a debounced timer (every 2 seconds while typing, after a 500ms pause)
- Numeric inputs (ratings, ticks) autosave immediately on change
- Show a small "saved" indicator (timestamp) somewhere unobtrusive on every page
- If save fails (network error), retry silently with exponential backoff. After 3 failures, show a non-blocking warning "Connection issue — your latest words may not be saved yet"
- Never block the UI on a save. Optimistic UI always.

### Implementation pattern
Use a custom React hook `useAutosave(entityKey, initialData, saveFunction)` that:
1. Holds local state
2. Debounces saves
3. Tracks save status ('idle', 'saving', 'saved', 'error')
4. Returns local state, an updater, and the status

Example consumers: every page that has writable inputs uses this hook against a single API endpoint that takes `(table, row_id, patch)`.

## 7. DESIGN SYSTEM — THE BLOOD PALETTE

### Colour tokens
```
--bone:        #F5F1E8   /* primary background */
--bone-warm:   #EDE6D6   /* slightly darker bone for cards on bone */
--ink:         #0E0E0E   /* primary text and dark surfaces */
--ink-soft:    #1A1A1A   /* secondary dark surface */
--blood:       #8B1A1A   /* primary accent — CTAs, active states, signature elements */
--blood-deep:  #6B1212   /* hover state for blood buttons */
--blood-faint: #F4E4E4   /* tinted background for blood-context cards (use sparingly) */
--steel:       #4A4A4A   /* secondary text on bone */
--ash:         #8B8680   /* tertiary text, subtle UI */
--line:        rgba(14,14,14,0.12)  /* default borders */
--line-strong: rgba(14,14,14,0.25)  /* stronger borders */
```

### Typography
- **UI font**: Inter (free, Google Fonts). Weights 400 and 500 only. Never 600 or 700.
- **Editorial font**: Fraunces or Crimson Pro for the rare moments — Ben's letter, pull quotes, the "letter to the man holding this," phase opener pages. Italic when used.
- Heading scale (mobile first):
  - h1: 28px / 32px desktop, weight 500, letter-spacing -0.01em
  - h2: 22px / 24px desktop, weight 500
  - h3: 16px, weight 500, ALL CAPS, letter-spacing 0.08em (used for "MORNING", "PHASE 1" etc.)
  - body: 16px, weight 400, line-height 1.7
  - small: 13px, weight 400 (for save timestamps, helper text)
  - micro: 11px, weight 500, letter-spacing 0.12em, ALL CAPS (for labels)

### Spacing rhythm
- Vertical between sections: 2rem (32px)
- Vertical between paragraph and prompt: 0.75rem (12px)
- Card padding: 1.5rem (24px)
- Input padding: 0.75rem 1rem (12px 16px)

### Components
- **Buttons (primary)**: blood background, bone text, no border, 4px radius, 12px 24px padding, ALL CAPS micro tracking. Hover: blood-deep.
- **Buttons (secondary)**: transparent background, ink border 1px, ink text, 4px radius, same padding. Hover: ink background, bone text.
- **Inputs**: bone-warm background, line border, 4px radius. Focus: 2px blood ring (offset 2px).
- **Textareas**: same as inputs but min-height 120px. Auto-resize on input.
- **Cards**: bone-warm background, line border 1px, 8px radius, 24px padding.
- **Active state cards (today's CTA)**: ink background, bone text, blood accent stripe on left edge (4px wide).
- **Rating selectors (1-5 or 1-10)**: row of pill buttons. Inactive: bone-warm, ash text. Active: ink background, bone text. Tap to set.
- **Checkboxes (habit grid, non-negotiables)**: 24px square, 4px radius. Unchecked: line border. Checked: blood fill, bone checkmark.
- **Dividers**: 1px line, generous vertical spacing.
- **Save indicator**: small ash text "Saved · 9:14 AM" — never bold, never noisy.

### Layout principles
- Max content width 720px on desktop
- Single column on mobile, never multi-column for writing pages
- Sticky bottom bar on mobile for "Save & continue" and "Save & exit" actions
- No modals for primary flows. Modals only for confirmations (e.g. "Delete this freeform entry?")
- Long pages should have a sticky progress indicator showing % of prompts answered

### Tone in microcopy
The app's microcopy follows the same tone as the journal itself. Examples:

- Empty input placeholder: "Write what's true." (not "Type your answer here")
- Save indicator: "Saved · 9:14 AM" (not "All changes saved successfully")
- Validation error: "This needs an answer to continue." (not "Please fill in this field")
- Loading: "Pulling your work…" (not "Loading…")
- Network error: "Connection's off. Your last words might not have saved." (not "Failed to save")
- Sign-out confirmation: "See you on the next page." (not "You have been signed out")
- 404: "There's nothing here. Head back to your journal." with a link.

Do not use exclamation marks. Do not use emoji anywhere in the UI.

## 8. INTERACTIVE WHEEL OF LIFE

The wheel is the most distinctive visual in the app. Build it as a custom SVG component.

### Behaviour
- 10 segments labelled: Career, Finance, Health, Social, Family, Love, Recreation, Contribution, Spirituality, Self-Image (clockwise from top)
- 10 concentric rings per segment representing rating 1 (centre) to 10 (outer edge)
- Tap or click a ring within a segment to set that segment's rating. The fill of the segment animates from the centre outward to the chosen ring.
- Filled portion: blood. Unfilled portion: bone-warm.
- Segment labels around the outside in micro caps.
- Below the wheel, a small indicator: "8 of 10 areas rated"
- Below that, a "Save & continue" button (disabled until all 10 are rated)
- On the post-90 wheel page, render the phase-1 wheel and the post-90 wheel side by side for comparison. On mobile, stack them with clear "BEFORE" and "AFTER" labels.

### State
The wheel reads from and writes to `wheel_entries.ratings` as `{ career: 6, finance: 4, ... }`. Autosaves on every tap.

## 9. HABIT GRID

The habit grid is the discipline scoreboard.

### Behaviour
- 5 rows (the user's 5 non-negotiables — they name them at the start of each phase)
- 28 columns (days 1-28 of the phase)
- Each cell is a checkbox. Tap to mark complete.
- Cells for future days are greyed out (cannot tick ahead)
- Today's column is highlighted with a blood underline
- Streak counter at the right of each row: "🔥 12-day streak" — actually, NO emoji. Use a small pill: "12 day streak" with blood text.
- Below the grid, a reflection prompt textarea.
- On mobile, the grid scrolls horizontally with the habit name column sticky on the left.

### State
Reads/writes `phase_habit_grids.ticks` as `{ "0": [true,true,false,...], "1": [...], ... }` — keys are habit indices, values are 28-element boolean arrays.

## 10. THE RESET PAGE

The most emotionally important page in the app.

### Trigger
Surfaces automatically on the dashboard when:
- The user has missed 3+ consecutive days, OR
- The user explicitly clicks "Fell off? Read this." from anywhere

### Page content
1. Headline: "If you're reading this, you fell off."
2. Sub: "Good. You're still here. That matters more than anything you missed."
3. Body copy (from the journal's reset page — already written)
4. Three prompts:
   - What did I miss, and how long was I off?
   - What was actually going on that pulled me away?
   - What's the one thing I'll do today, before bed, to pick this back up?
5. Big blood button: "I'm back. Take me to today."
6. Submitting writes a `reset_events` row and routes to `/journal/day/[currentDay]`.

The page never blames, never asks for explanations, never makes him feel worse. It's a hand-up, not a guilt-trip.

## 11. FONT MATTER & ONE-TIME PAGES

These are the pages that are filled in once and then read-only forever (with an "edit" affordance for changes).

After completion, displaying these pages should look like a finished artifact — printed type on bone — not an editable form. This is what makes the work feel permanent and earned.

When the user lands on a completed front-matter page, render the printed view by default with a small "Edit" button in the corner. Editing reverts to the form view.

Pages with this treatment:
- Line in the Sand
- Who I'm Becoming
- Standards (start of phase 2)
- Brotherhood (start of phase 2)
- Legacy (start of phase 3)

This is a small but meaningful detail. The man finishes these pages and they become a permanent statement, not a form he can re-edit casually.

## 13. SECURITY & PRIVACY

- Every database table has Row Level Security ON. Users can only read/write their own rows.
- Authentication is Google-only via Supabase Auth. No password storage.
- Invite codes are single-use and stored hashed where practical.
- No analytics tracking of journal content. Only anonymous usage events (page views, feature use) if any.
- Privacy policy and terms required before launch — separate static pages.
- The founder cannot see client writing. Period. This is a brand promise that earns trust with the recovery audience.

2. Walk through onboarding and the front matter pages
3. Complete the wheel of life, the gap, four pillars, integrity inventory, man comparison, perfect morning, perfect night
